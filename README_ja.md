# LoveCa × Tabletop Simulator

[简体中文](README.md) | [English](README_en.md) | **日本語**

今すぐ[steam workshop](https://steamcommunity.com/sharedfiles/filedetails/?id=3823101966)で遊べる。

**ラブライブ！シリーズ オフィシャルカードゲーム（ラブカ／LoveCa）**向けの非公式 TTS Lua 補助スクリプトです。デッキ導入、カード情報の表示、盤面計算、正負の数値マーカー、Live のハート条件のリアルタイム判定に対応します。

能力の処理、ドロー、コストの支払い、カードの移動、ターン進行はプレイヤーが行います。そのまま読み込める完全な TTS シーンや、全カードを収録したオフラインデータベースは含まれていません。

## 機能

- **デッキ導入**：完全なカード番号で公式サイトを検索し、メインデッキとエネルギーデッキを生成します。生成枚数とインスタンスの重複も確認します。
- **カード情報**：ホバー説明に種類、コスト、ハート、ブレード、スコア、エール情報、能力、ラブカポイントを表示し、原文データとアイコン表記を保持します。
- **盤面計算**：双方のステージ、Live、エール、エネルギーを別々に集計し、1 秒ごとに更新します。非公開カード、不明な配置、データ異常があれば確認を促します。
- **数値補正**：ハート、ブレード、スコアの正負マーカーを、配置エリアに応じて集計へ反映します。
- **Live 判定**：ステージとエールのハートを共有し、すべての Live をまとめて判定します。補正値が変わると自動で再計算します。
- **先攻・後攻の決定**：先攻／後攻を選ぶプレイヤーを着席者から抽選し、GM と観戦者を除外します。
- **3 言語切り替え**：「言語」で中文、日本語、English を選択すると、テーブル全体の固定文言とカード説明の項目名が切り替わります。

## 動作環境とテーブルの準備

- **Tabletop Simulator**。ゲーム内のカード検索、カード画像、マーカーテクスチャにはネットワーク接続が必要です。
- **Python 3**。ビルドと任意の同期ツールに使用します。標準ライブラリのみを使うため、Python の追加パッケージは不要です。
- 以下のコマンドは**プロジェクトのルートディレクトリ**から実行します。PowerShell の例は **PowerShell 7** を使用します。

盤面計算には、本プロジェクトのエリア構成に合う 2 人用のプレイマットが必要です。初期設定は [`ground/field_statistics.lua`](ground/field_statistics.lua) の `FIELD_DEFAULTS` にあり、White は `0e661d`、Pink は `bab5f6` に対応します。これらは**開発用シーンのオブジェクト GUID**であり、新しいテーブルで共通に使える番号ではありません。

別のシーンに適用する場合は、プレイマットの GUID、サイズ、向き、ローカルエリアを確認し、設定を変更して再ビルドしてください。既存セーブでは `field.config` がソースの初期設定より優先されるため、初期設定の変更だけでは古いセーブは移行されません。

## クイックスタート

### 1. Global スクリプトをビルドする

```powershell
python tools/build_importer.py
```

生成ファイルは [`ground/import_cards.lua`](ground/import_cards.lua) です。共通ロジック、言語辞書、盤面計算、マーカースクリプト、インポーターが含まれています。**生成ファイルを直接編集しないでください。**

### 2. TTS に導入する

1. 対応するテーブルを開き、まずゲーム内で最新のシーンを保存します。新しいスロットに保存した場合は、そのセーブを読み込んでから続けてください。
2. TTS のスクリプトエディターを開き、**Global** を選択します。
3. `ground/import_cards.lua` の内容をすべて Global に貼り付けます。
4. **Save & Play** を実行し、左側のボタンとプレイマットのエリアを確認してから、再度ゲームを保存します。

**Save & Play はシーンを再読み込みするため、未保存の配置が元に戻る場合があります。** スクリプトを個別のカードに貼り付けたり、過去の復元用セーブで現在のゲームを上書きしたりしないでください。

### 3. デッキを導入する

「デッキ導入」をクリックし、1 行につき 1 種類の**完全なカード番号と枚数**を入力します。例：

```text
PL!-bp3-021-SRL 2
PL!-pb2-000-R 4
PL!S-PR-034-PR+ 6
```

- カード番号にはレアリティを含めてください。半角 `+` と全角 `＋` の両方に対応します。
- 空行と `#` で始まる行全体のコメントは無視します。同じカードの重複行は枚数を合算します。
- 1 回の上限は 200 枚、60 種類です。これは導入処理の保護であり、デッキの適法性判定ではありません。
- [`deck/`](deck/) 内の `.tts.txt` リストを直接貼り付けられます。`.yaml` は参考デッキ資料であり、導入欄では解析しません。
- データを検証してからカードを生成します。セーブを読み込んでも、自動で再導入することはありません。

この例は入力形式を示すもので、完全かつ適法なデッキではありません。ラブカポイントには [`card/points.json`](card/points.json) の **2026-08-08** 時点のスナップショットを使います。使用前に最新の大会規定を確認してください。

## ゲーム内操作

### 盤面計算と Live 判定

「盤面計算」で双方の集計を確認できます。データは 1 秒ごとに自動更新され、「更新」と「詳細」も利用できます。

- ステージのメンバーは Active／Wait のどちらでもハートを加算します。ブレードを加算するのは Active のメンバーだけです。
- エールエリアは、各プレイヤーのマット外側、本人から見て左側にある緑色の枠です。まず個別のカードを公開し、必要に応じて重ねてください。
- ステージ、Live、配置済みエネルギーは 1 枚ずつ置いてください。これらのエリアでは、個別カードの代わりにカードの束を置くことはできません。
- 判定では**すべての Live の必要条件をまとめ、1 つの共有ハートプールを使います**。ハートを重複して使うことはできません。ALL は指定色を補い、無色は総数のみに加算されます。
- 関連カードが非公開、配置に異常がある、または Live がない場合は未判定になります。補正後の最終ハート数が負の場合は、その数値を保持して確認を促します。
- 禁止効果は「Live不可（効果・手動）」で指定します。ほかの能力も先に手動で処理し、現在の数値で判定してください。

ここでの成功／失敗は**現在のハート条件の結果**です。最終スコアの比較・決着、成功した Live の移動、ゲーム全体の勝敗判定は自動で行いません。

### 数値マーカー

「数値マーカー」でプレイヤー、リソース、初期値、配置先を選び、マーカーを作成します。

- 図柄をドラッグして移動します。外側の数字は左クリックで `+1`、右クリックで `−1` します。
- 右クリックメニューで整数入力、符号反転、ゼロへのリセット、削除ができます。
- `M1～M3` は 3 人のメンバー、`L1～L3` は 3 つの Live に対応します。ほかに Live 合計スコア、エール補正、保管エリアがあります。
- 対応するエリアのマーカーだけが補正に反映され、保管中は無効です。たとえば ALL はエール補正用であり、メンバー補正には使いません。
- メンバー／Live マーカーは配置時のカードに紐づきます。対象を変更するときは、保管エリアに戻してから新しい対象の欄に置いてください。以前の補正が自動で引き継がれるのを防ぎます。

### 非公開カード 処理エリア

効果によりカードを非公開で確認・選択するときは、自分のプレイヤー色の非公開エリアを使います。処理後は効果の指示に従い、手札、控え室などの指定された場所へ移動してください。両エリアの中央にタイトルと処理の案内を表示し、所有者や「専用」の表記は付けません。表示は言語切り替えに対応し、カードのクリックやドラッグを妨げません。

### 先攻・後攻の決定と言語

「先攻・後攻を決定」は、どの着席プレイヤーが先攻／後攻を**選ぶか**を決める機能です。先攻／後攻そのものを自動で選ぶわけではありません。GM（Black）と観戦者（Grey）は除外し、通常のプレイヤー色に着席したホストは参加できます。抽選結果は「[Whiteプレイヤー]が先攻・後攻を決定」と表示します。

「言語」では中文、日本語、English を選択でき、選択はスクリプト状態とともに保存されます。入口は常に表示され、ポップアップは同時に 1 つだけ開き、共通の左上位置から表示されます。

固定ラベルと説明は 3 言語に対応しています。カード名、作品名、ユニット名、商品名、未翻訳の能力本文は日本語の原文を保持します。カード画像やプレイマット画像の印刷文字は描き直しません。言語変更時に既存デッキは分解せず、中の個別カードは取り出したときに説明を更新します。

## 任意：同期ツールを使う

手動導入の代わりに [`tools/sync_tts.py`](tools/sync_tts.py) を利用できます。先に TTS の **External Editor API** を有効にしてください。ローカルのループバックアドレスのポート `39999` にリクエストを送り、`39998` で応答を受け取ります。同時に実行する同期クライアントは 1 つだけにしてください。

外部セーブディレクトリはプロジェクト内に固定していません。**現在のプロジェクトディレクトリからの相対パス**で、実際の TTS Saves の場所を入力します。

```powershell
$ttsSaves = Read-Host 'TTS Saves ディレクトリの相対パスを入力してください'

# 実行中のソース、UI、スクリプト状態と既存のディスクセーブを保存します。ゲームは変更しません。
python tools/sync_tts.py --save-dir "$ttsSaves" --capture-only
```

指定ディレクトリには `TS_AutoSave*.json` が必要です。このバックアップは**テーブル全体のリアルタイムスナップショットではなく**、ゲーム内保存の代わりにはなりません。

本同期の前にゲーム内で最新のテーブルを保存してください。新しいスロットに保存した場合は、そのセーブを読み込み、Save & Play の対象を同じファイルに揃えます。そのとき実際に保存したファイル名を入力し、過去のスロット番号を使い回さないでください。

```powershell
$saveName = Read-Host '保存したばかりのファイル名を入力してください。例：TS_Save_3.json'
$savedGame = Join-Path $ttsSaves $saveName
python tools/sync_tts.py --save-dir "$ttsSaves" --reload --saved-game "$savedGame"
```

このコマンドはバックアップを作成し、現場のオブジェクトと変換を照合します。読み込み中のセーブと指定ファイルが異なる場合は、再読み込み前に停止します。Save & Play 後にソース、エディターキャッシュ、変換、永続状態を検証し、すべて通過してから指定セーブを更新します。失敗した場合は表示された案内に従い、差分チェックを省略して強制同期しないでください。

`--apply` は**再読み込みしないホットプレビュー**です。エディターキャッシュとネイティブセーブが更新されたことを意味しません。復元資料はローカルの `.tts-backups/` に保存します。古いバックアップを復元する前に、その時点の最新のゲームを保存してください。

ソースモジュールを変更したら再ビルドしてください。Python ツールのコンパイル確認は次のコマンドで行えます。

```powershell
python -m py_compile tools/build_importer.py tools/sync_tts.py
```

ローカルの IDE／アシスタント設定、Python キャッシュ、`.tts-backups/` は `.gitignore` で共有対象から除外しています。手動で圧縮するときも除外してください。公式サービスの URL、公開画像の出典、オブジェクト GUID、TTS プロトコルのポートは個人のファイルパスではありません。

## 能力翻訳の提案と現在の状況

能力本文はカードごとに異なりますが、同じバージョンなら訳文を再利用できます。ゲームから毎回翻訳サービスを呼ぶより、**基礎カード番号と原文バージョンをキーに、校閲済み訳文をオフライン管理する方法**を推奨します。

1. ルール用語を統一し、`{{ファイル名|原文alt}}` のアイコン表記を保持して、本文だけを翻訳します。
2. 日本語原文のスナップショット、訳文、出典、校閲状態を保存し、数値、条件、対象、任意行動、継続時間を確認します。
3. 異なるレアリティの間でも、原文が完全に同じ場合だけ訳文を再利用します。公式原文が変わったら、日本語に戻して再確認します。
4. 校閲済みの中国語本文には `translations.zh.ability`、英語本文には `translations.en.ability` を使えます。訳文は数値計算に使いません。

詳しい提案と実カードの例は[研究記録の 39.2 節](loveca-tts-research.md)を参照してください。**現在、一括した中国語／英語の能力訳文は含まれておらず、自動翻訳サービスも接続していません。**
