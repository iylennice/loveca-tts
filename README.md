# LoveCa × Tabletop Simulator

**简体中文** | [English](README_en.md) | [日本語](README_ja.md)

面向 **LoveLive! 系列官方卡牌游戏（LoveCa／ラブカ）** 的非官方 TTS Lua 辅助脚本：导入牌组、查看卡牌信息、统计场面、使用正负数值标记，并实时显示 Live 的爱心条件是否满足。

技能处理、抽牌、支付费用、移动卡牌和回合操作仍由玩家完成。项目不包含可直接载入的完整 TTS 场景，也不提供全量离线卡牌数据库。

## 功能

- **牌组导入**：按完整卡号查询官网数据，生成主牌组与能量牌组，检查生成数量及重复实例。
- **卡牌信息**：在悬停说明中显示类型、费用、爱心、应援棒（Blade）、分数、应援信息、能力及构筑积分；保留原始数据和图标标记。
- **场面计算**：分别统计双方舞台、Live、应援和能量区，每秒刷新；未公开、摆放不明或数据异常时提示检查。
- **数值补正**：爱心、应援棒和分数支持带正负号的标记，按所在区域进入统计。
- **Live 判定**：使用舞台与应援的共享爱心池，联合检查全部 Live；补正变化后自动重算。
- **决定先后手**：从已入座玩家中抽取由谁选择先攻／后攻，排除 GM 和旁观者。
- **三语言切换**：「语言」可选择中文、日本語或 English，对全房生效；固定文案和卡牌说明栏名随之切换。

## 环境与场地准备

- **Tabletop Simulator**；游戏内卡牌查询、卡图及标记贴图需要网络访问。
- **Python 3**：用于构建和可选同步工具，仅使用标准库，无须安装 Python 第三方包。
- 下文命令从**项目根目录**运行；PowerShell 示例使用 **PowerShell 7**。

场面统计依赖与本项目分区匹配的双人桌垫。默认配置在 [`ground/field_statistics.lua`](ground/field_statistics.lua) 的 `FIELD_DEFAULTS` 中：White 对应 `0e661d`，Pink 对应 `bab5f6`。这些是开发场景的**物体 GUID**，不是任意新桌面的通用编号。

若适配其他场景，需要核对桌垫 GUID、尺寸、朝向及局部分区，再修改配置并重新构建。已有存档中的 `field.config` 优先于源码默认值，不能只修改默认值就假定旧存档已迁移。

## 快速开始

### 1. 构建 Global 脚本

```powershell
python tools/build_importer.py
```

生成文件为 [`ground/import_cards.lua`](ground/import_cards.lua)。它已经包含公共逻辑、词表、场面计算、标记脚本和导入器，**不要直接编辑生成文件**。

### 2. 安装到 TTS

1. 打开适配的游戏桌面，先在游戏内保存最新场景。
2. 打开 TTS 脚本编辑器，选择 **Global**。
3. 将 `ground/import_cards.lua` 的完整内容放入 Global。
4. 执行 **Save & Play**，检查左侧入口及桌垫区域，然后再次保存游戏。

**Save & Play 会重载场景，未保存的摆放可能回退。** 不要将脚本粘贴到某张卡牌上，也不要用历史恢复存档覆盖当前牌局。

### 3. 导入牌组

点击「导入牌组」，每行填写一种卡的**完整卡号及张数**，例如：

```text
PL!-bp3-021-SRL 2
PL!-pb2-000-R 4
PL!S-PR-034-PR+ 6
```

- 卡号必须包含稀有度；支持半角 `+` 和全角 `＋`。
- 忽略空行和以 `#` 开头的整行注释；同卡重复行合并数量。
- 单批上限为 200 张、60 种，这是导入保护，不是牌组合法性判定。
- 可直接粘贴 [`deck/`](deck/) 中的 `.tts.txt` 清单；`.yaml` 是牌组参考资料，导入框不解析 YAML。
- 点击导入后先校验数据，再生成卡牌；加载存档不会自动重复导入。

示例仅说明输入格式，不是一副完整合法牌组。构筑积分使用 [`card/points.json`](card/points.json) 保存的 **2026-08-08** 快照，使用前应核对最新赛事规定。

## 游戏内操作

### 场面计算与 Live 判定

点击「场面计算」查看双方统计，数据每秒自动刷新，也可以点「刷新」或「详情」。

- 舞台成员无论就绪／休息均贡献爱心，只有就绪成员贡献应援棒。
- 应援区位于各自桌垫外侧、玩家左手边的绿色框；先翻开散牌，再按需要合堆。
- 舞台、Live 和已放置能量请逐张摆放；这些区域不接受牌堆代替独立卡。
- 判定使用**所有 Live 的联合需求和同一个资源池**，不能重复使用爱心；ALL 可以补指定颜色，无色只贡献总量。
- 存在未公开相关卡、摆放异常或无 Live 时显示未判定。补正后的最终爱心数量为负时保留负数并提示确认。
- 「禁止 Live（效果·手动）」由玩家处理禁止效果；其他技能也需要人工先处理，再以当前数值判定。

这里的成功／失败是**当前爱心条件的结果**，不会自动结算双方比分、移动成功 Live 或判断整局胜负。

### 数值标记

点击「数值标记」，选择玩家、资源、初始值和区域，再创建标记。

- 拖动图案移动；点击外侧数字，左键 `+1`、右键 `−1`。
- 右键菜单支持输入整数、正负反转、归零和删除。
- `M1～M3` 对应三名成员，`L1～L3` 对应三张 Live；另有 Live 总分、应援补正和保管区。
- 只有适用区域中的标记参与补正，保管区不生效；例如 ALL 用于应援补正，不是成员补正。
- 成员／Live 标记会关联放置时的卡牌。更换对象时先放回保管区，再放到新对象的栏位，避免旧补正自动继承。

### 决定先后手与语言

「决定先后手」只决定由哪位入座玩家**选择**先攻／后攻，不替其作实际选择。GM（Black）及旁观者（Grey）不参与，正常入座的房主可以参与。结果显示为「由[白色玩家]决定先后手」。

「语言／言語／Language」提供中文、日本語和 English，选择随脚本状态保存。入口保持可见，各弹窗互斥，打开时使用统一左上起点。

固定标签与说明支持三种语言；卡名、作品名、组合名、商品名和能力正文缺译时保留日文，卡图与桌垫图片内的印刷文字不重绘。已有牌堆不会因切换语言被拆分，内部单卡在取出时更新说明。

## 可选：使用同步工具

手动安装之外，可使用 [`tools/sync_tts.py`](tools/sync_tts.py)。先启用 TTS 的 **External Editor API**；工具通过本机回环地址的 `39999` 端口发送请求，在 `39998` 接收回复，同一时间只运行一个同步客户端。

外部存档目录不写死在项目中，以下交互输入使用**相对当前项目目录的实际 TTS Saves 路径**：

```powershell
$ttsSaves = Read-Host '输入 TTS Saves 目录的相对路径'

# 只备份运行中的源码、UI、脚本状态及已有磁盘存档，不改动游戏。
python tools/sync_tts.py --save-dir "$ttsSaves" --capture-only
```

工具要求指定目录中已有 `TS_AutoSave*.json`。这份备份**不是实时全桌场景快照**，不能代替游戏内保存。

正式同步前，先在游戏内保存最新桌面，再输入这次实际保存的文件名，不要沿用历史槽号：

```powershell
$saveName = Read-Host '输入刚保存的文件名，例如 TS_Save_3.json'
$savedGame = Join-Path $ttsSaves $saveName
python tools/sync_tts.py --save-dir "$ttsSaves" --reload --saved-game "$savedGame"
```

该命令会备份、核对现场物体及变换，再执行 Save & Play，并验证运行脚本、编辑器缓存和指定存档。检查失败时按提示处理，不跳过差异检查强行同步。

`--apply` 是**不重载的热预览**，不代表编辑器缓存和原生存档已经更新。恢复资料保存在本地 `.tts-backups/`，恢复前仍须保存届时最新牌局。

## 能力中文翻译：建议与当前状态

能力正文虽因卡而异，但同一版本可复用译文。首选**离线维护、按基础卡号和原文版本索引的审校译文**，而不是游戏内逐次调用翻译服务：

1. 统一规则术语，保留 `{{文件名|原始alt}}` 图标标记，只翻译正文。
2. 保存日文原文快照、中文译文、来源和审校状态；核对数值、条件、目标、可选动作及持续时间。
3. 不同稀有度仅在原文完全相同时复用译文；官方原文变化后回退日文并待复核。
4. 审核后的中文正文可使用现有 `translations.zh.ability` 展示入口，英语对应 `translations.en.ability`；译文不参与数值计算。

完整建议及真实卡牌例子见 [研究记录第 39.2 节](loveca-tts-research.md)。**目前未内置批量能力中文／英语译文，也未接入自动翻译服务。**
